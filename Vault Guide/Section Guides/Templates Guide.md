# Templates

[[ReadMe|Home]] · [[Setup|Setup]]

Templates define the starting content for new entries. Keep them in the Templates folder with these exact filenames:

| Template | Used by | Destination |
| --- | --- | --- |
| Daily Note.md | Daily notes core command | Daily Notes/YYYY-MM-DD.md |
| Meeting.md | New Meeting | Meetings/date - name.md |
| Project.md | New Project | Projects/name/name.md |
| Note.md | New Note | Notes/date - name.md |
| KB Entry.md | New KB Article | KB/date - name.md |
| KB Application.md | New KB Application | KB/name/name.md |

## Safe customization

Open a template in Source mode to change its headings, explanatory text, or blank fields. Preserve its date/title placeholders, type property, relationship properties, and query/button blocks unless intentionally changing the workflow.

Daily Note uses the core Daily notes template handling. The creation buttons fill the title and ISO date placeholders in the other templates and insert selected relationship links. Prefer the buttons for those templates: manually inserting them does not create folders, select relationships, or record a daily reference. Do not assume the core Templates command resolves the custom title placeholder.

The shared creation script expects Templates/Meeting.md, Project.md, Note.md, KB Entry.md, and KB Application.md. Renaming one requires updating the shared script. New ToDo is generated by that script; a separate New ToDo.md file is not required and is not present in the inspected vault.

## What changes affect existing notes?

- Template content changes affect newly created entries only.
- Shared System/Scripts/VaultEntryButtons.js changes affect buttons in notes that call that shared view.
- Existing entries retain their sections and queries. Copy only the required sections when updating them; never paste a complete template over filled-in content.

Keep section guides in Vault Guide/Section Guides, not Templates. Do not store ordinary work entries in Templates.
